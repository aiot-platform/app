## 一、产品概述

### 1.1 产品定位
设备安装在宠物店内，宠物主人通过面板远程看到并听到自己的宠物，同时了解它的状态、环境和一天的动态。核心任务：设备在线且店铺开放时，点击“实时流”看到宠物店那一侧的音视频画面。

### 1.2 核心价值
- **看得到**：首页主视觉是实时画面，一步进入。
- **看得懂**：设备 AI 识别宠物行为（休息、睡觉、玩耍、进食、饮水），叠加活跃度与舍内温湿度，不用盯着画面也能放心。
- **有互动**：抓拍留念、远程投喂零食、对讲，缓解分离焦虑。
- **有交代**：日报、店员留言、动态时间线，让主人知道宠物一天的情况。

### 1.3 设计目标
- 视觉面向宠物主人：暖橙主色、圆润卡片、宠物头像和状态图标，避免“监控设备”的冷感。
- 首屏回答：我的宠物在不在、在做什么、状态好不好、怎么看。
- 设备回报为最终真值；平台数据与物模型数据分开标注。
- 可选能力缺失时逐级隐藏，不留空卡与空入口。

## 二、物模型定义

引用文件：`宠物店音视频设备物模型.json`。

### 2.1 接入必选规则
产品接入策略建议（JSON 中以 `required` 标注）：属性 `av_status`；服务 `start_live`、`stop_live`。必选项缺失时配置发布阶段应阻断。其余均为可选。设备在线/离线来自平台连接状态。

### 2.2 PROPERTY（共 14 个，R 9 / RW 5）

| ID | 名称 | Code | 类型 | 权限 | 必选 | 取值范围/枚举 | 单位/步长 |
|---:|---|---|---|---|---|---|---|
| 1 | 音视频状态 | av_status | ENUM | R | 是 | 0 空闲；1 推流中；2 对讲中；3 异常 | - |
| 2 | 画质 | video_quality | ENUM | RW | 否 | 1 流畅；2 标清；3 高清；4 超清 | - |
| 3 | 设备拾音开关 | mic_switch | BOOL | RW | 否 | 0 关闭；1 开启 | - |
| 4 | 设备扬声器音量 | speaker_volume | INT | RW | 否 | 0～100 | % / 10 |
| 5 | 夜视模式 | night_vision | ENUM | RW | 否 | 0 自动；1 始终开启；2 始终关闭 | - |
| 6 | 画面翻转 | image_flip | ENUM | RW | 否 | 0 正常；1 旋转180度 | - |
| 7 | 当前观看人数 | viewer_count | INT | R | 否 | 0～4 | 人 / 1 |
| 8 | Wi-Fi 信号强度 | wifi_rssi | INT | R | 否 | -100～0 | dBm / 1 |
| 9 | 存储卡状态 | sd_status | ENUM | R | 否 | 0 未插卡；1 正常；2 异常；3 格式化中 | - |
| 10 | 宠物状态 | pet_activity | ENUM | R | 否 | 0 未检测到宠物；1 休息；2 睡觉；3 玩耍；4 进食；5 饮水 | - |
| 11 | 活跃度 | activity_level | INT | R | 否 | 0～100 | % / 1 |
| 12 | 舍内温度 | env_temperature | FLOAT | R | 否 | -20～60 | ℃ / 0.1 |
| 13 | 舍内湿度 | env_humidity | INT | R | 否 | 0～100 | % / 1 |
| 14 | 今日剩余零食次数 | treat_left | INT | R | 否 | 0～10 | 次 / 1 |

ID 当前连续 1～14，实现不得依赖连续性。

### 2.3 EVENT（共 4 个：ERROR 1 / WARN 2 / INFO 1）

| 事件 ID | 名称 | Code | 级别 | 输出参数 | 触发与恢复 |
|---:|---|---|---|---|---|
| 101 | 推流异常 | stream_error | ERROR | `error_code`：0 编码器故障；1 摄像头无信号；2 网络拥塞 | 推流失败时上报，`av_status` 同步为异常；恢复推流后解除 |
| 102 | 存储卡异常 | sd_card_error | WARN | `sd_status`：0 未插卡；1 正常；2 异常；3 格式化中 | 读写异常时上报，不影响实时流；`sd_status` 回到正常后解除 |
| 103 | 吠叫提醒 | bark_alert | INFO | `volume_db`：0～120 dB | 识别到持续吠叫时上报；仅提醒，无恢复事件，提示可手动关闭 |
| 104 | 舍内环境异常 | env_abnormal | WARN | `abnormal_type`：0 温度过高；1 温度过低；2 湿度异常；`value`：-20～100 | 温湿度超出舒适范围时上报；回到范围内后解除 |

事件输出参数不计入属性。

### 2.4 SERVICE（共 4 个，均为异步）

| 服务 ID | 名称 | Code | 输入 | 输出 `result` |
|---:|---|---|---|---|
| 201 | 开启实时流 | start_live | `quality`：1 流畅；2 标清；3 高清；4 超清 | 0 已开始推流；1 设备忙；2 观看人数已满；3 摄像头无信号 |
| 202 | 停止实时流 | stop_live | 无 | 0 已停止；1 当前未推流 |
| 203 | 抓拍 | snapshot | 无 | 0 抓拍成功；1 未在推流；2 存储失败 |
| 204 | 投喂零食 | dispense_treat | 无 | 0 已投喂；1 今日次数已用完；2 设备忙；3 余粮不足 |

### 2.5 平台能力（非物模型）
设备在线状态、实时音视频传输通道、宠物档案（名字、品种、年龄、寄养天数）、店铺信息与营业时段、今日日报、店员留言、动态时间线、相册存储。这些不得写成物模型属性。

## 三、信息架构与动态适配

### 3.1 页面结构
- **实时（首页）**：告警条 → 宠物档案头部 → 播放器 → 宠物状态卡（含环境）→ 快捷操作（抓拍、投喂零食、和它说话）。
- **动态**：今日日报、店员留言、今日动态时间线。
- **相册**：抓拍照片网格，点击查看大图。
- **更多**：观看设置（画质、店内收音、对讲音量）、画面设置（夜视模式、画面翻转）、设备状态（观看人数、Wi-Fi、存储卡）。

### 3.2 导航规则
- 底部导航最多 4 项：实时、动态、相册、更多。“动态”为平台能力，常驻。
- `snapshot` 服务不存在时隐藏“相册”；“更多”三个分组全部为空时隐藏“更多”。入口减少后剩余入口重新等宽排布。
- 当前页因能力移除失效时，自动返回“实时”，并关闭浮层。
- 返回优先级：最上层浮层 → 当前非首页 Tab → 首页。

### 3.3 演示边界
原型左侧“演示场景”与右侧“核心能力说明”仅用于评审，不属于正式 App。画面中的宠物与店铺为模拟，正式版由设备推流提供。字段、控件、局部布局的缺失降级见第四章各功能。

## 四、功能详述

原型：`宠物看护控制面板.html`。

### 4.1 实时流（核心功能）
**需求来源**：SERVICE `start_live`(201)、`stop_live`(202)；PROPERTY `av_status`(1)；平台在线状态、店铺营业时段。必选。
**业务逻辑**：设备在线且店铺开放时，点击“实时流”，用户看到并听到宠物店一侧的实时音视频。
**产品逻辑**：
1. 播放器初始为封面态，文案“看看{宠物名}在店里的样子”，显示“实时流”按钮。
2. 点击后进入“连接中”（转圈 + “正在连接{店名}的摄像头…”），App 调用 `start_live`，`quality` 取当前 `video_quality`；该属性不存在时取“高清”。
3. 服务返回 `result=0` 且 `av_status` 回报为推流中（1）后，显示实时画面，叠加 LIVE 标记和观看时长。
4. 点击停止调用 `stop_live`；最后一个观看端退出后设备回到空闲。
**展示与自适应规则**：
- 叠层：左上 LIVE + 时长；右上观看人数、Wi-Fi 信号（属性不存在则隐藏，无回报显示 `--`）；左下“宠物状态气泡”（`pet_activity` 不存在则隐藏）；底栏含静音、画质、对讲、全屏、停止。
- `video_quality` 不存在：画质按钮改为只读标签。`mic_switch` 不存在：隐藏声量条与“店内收音已关”提示。
- “静音”仅控制观看端本地播放，不下发设备，不等同于 `mic_switch`。
**交互说明**：连接超时阈值 10 秒。失败时封面显示原因和“重试”：`result=1` 设备忙，`result=2` 观看人数已满，`result=3` 摄像头无信号，超时显示“连接超时，请检查网络后重试”。
**状态与异常**：
- 设备离线：封面灰色，“设备离线，暂时看不到{宠物名}”，按钮置灰。
- 店铺休息时段（平台）：封面显示“店铺休息时段，暂不开放实时画面”和开放时间，按钮置灰，不调用服务；播放中遇到休息时段立即停止播放。
- 播放中设备离线或 `av_status` 变为非 1/2：立即停止并显示对应封面，不保留最后一帧。
- `av_status=3`：封面显示异常提示与“重试”；未知值按未知状态处理，不播放。
- 设备已在推流但本端未观看：封面提示“摄像头正在推流，点击观看”。

### 4.2 宠物档案头部
**需求来源**：平台能力（宠物档案、店铺信息）；在线状态。
**展示规则**：宠物头像、名字、品种·年龄、店名·寄养第 N 天、在线/离线标签。档案缺失时只显示设备名与在线标签；无头像时用默认宠物头像。

### 4.3 宠物状态与活跃度
**需求来源**：`pet_activity`(10)、`activity_level`(11)，R 可选。
**业务逻辑**：让主人不看画面也能知道宠物在做什么、是否活跃。
**展示与自适应规则**：
- 状态卡左侧为行为图标和文案（如“正在玩耍”）；右侧圆环显示活跃度百分比。图标与底色按状态区分。
- `pet_activity=0` 显示“未检测到宠物”，播放器气泡显示同文案，不显示宠物名。未知枚举值显示“未知”，不默认选中任何一项。
- 无回报显示 `--`；活跃度 0 是有效值，圆环为空但显示 0%。
- 仅有其中一项时只显示对应部分；两项都不存在时，若舍内环境也不存在，则整张状态卡隐藏。
- 离线时保留最后有效值并提示“设备离线，显示最后一次状态”。
**交互说明**：只读，无写入控件。

### 4.4 舍内环境
**需求来源**：`env_temperature`(12)、`env_humidity`(13)，R 可选。
**展示规则**：位于状态卡下的两个小卡片。温度显示一位小数，并给出“舒适/偏热/偏冷”标签：18℃～28℃ 为舒适（产品建议，可由店铺配置），高于 28℃ 偏热，低于 18℃ 偏冷。湿度显示整数。字段不存在则隐藏对应卡片；两项都不存在则隐藏整行；无回报显示 `--`。
**与告警关系**：超出范围时，设备上报 `env_abnormal`(104)，首页出现告警条（见 4.10）。

### 4.5 抓拍与相册
**需求来源**：SERVICE `snapshot`(203)；平台相册存储。
**产品逻辑**：仅在播放中可用。点击后调用 `snapshot`，`result=0` 提示“已抓拍，保存到相册”；`result=1` 提示“先点实时流，再抓拍哦”；`result=2` 提示存储失败。照片写入平台相册，并在“相册”Tab 角标显示新增张数，进入相册后清零。
**展示与自适应规则**：相册为双列网格，显示拍摄时间，点击打开大图浮层。无照片时显示空态“还没有照片，观看实时流时点‘抓拍’…”。`snapshot` 服务不存在：隐藏“抓拍”按钮和“相册”Tab。
**状态与异常**：未在播放时按钮置灰；离线不可用。

### 4.6 投喂零食
**需求来源**：SERVICE `dispense_treat`(204)；PROPERTY `treat_left`(14)。
**业务逻辑**：让主人远程给宠物一份零食，增加互动。
**产品逻辑**：点击“投喂零食”调用服务，按钮显示“投喂中…”并禁止重复点击。`result=0` 时提示“{宠物名}收到零食啦～”，`treat_left` 以设备回报为准递减，并向“今日动态”写入一条“你给{宠物名}投喂了一份零食”。`result=1` 提示“今日零食已投喂完”；`result=2` 提示设备忙；`result=3` 提示余粮不足，店员将收到通知（平台）。
**展示与自适应规则**：按钮副文案“今日还可 N 次”；`treat_left=0` 时按钮置灰并显示“今日已投完”；`treat_left` 不存在时不显示副文案，也不做本地次数限制，以服务返回为准。服务不存在时隐藏按钮，其余快捷按钮重新等分。
**状态与异常**：离线禁用；失败提示后恢复，不扣减次数；店铺休息时段是否允许投喂由店铺策略决定（待确认）。

### 4.7 对讲
**需求来源**：平台音频通道；`av_status`=2。
**产品逻辑**：仅播放中可用。开启后观看端声音由店内扬声器播放，`av_status` 变为对讲中；再次点击结束，回到推流中。播放器底栏与首页快捷区的按钮状态同步。
**状态与异常**：离线或停止播放时不可用；对讲通道由平台提供，协议待确认。

### 4.8 观看设置：画质、店内收音、对讲音量
**需求来源**：`video_quality`(2)、`mic_switch`(3)、`speaker_volume`(4)，RW 可选，位于“更多”页观看设置；画质同时可在播放器底栏打开。
**交互与自适应规则**：
- 画质：点击打开底部浮层（点击选择 + 确认）。只更新临时值，“确定”在未变化时禁用，关闭、遮罩、返回均丢弃临时值。选项按实际枚举生成；仅剩 1 项时只提示当前支持项，不弹层；当前值不在枚举内时显示“未知”，不默认选中首项。
- 店内收音：开关点击即提交，提交中禁用；开启“观看时可听到店里的声音”，关闭“仅有画面”。无回报不默认显示“关闭”。
- 对讲音量：加减按钮每次 10，0 与 100 处对应按钮禁用，不下发越界值；0 为有效值。
- 三项全部不存在时隐藏“观看设置”分组。
**状态与异常**：离线禁用；失败、超时（5 秒）恢复设备原值并提示“设置失败，已恢复设备当前值”；旧回包不覆盖新操作。

### 4.9 画面设置
**需求来源**：`night_vision`(5)、`image_flip`(6)，RW 可选。
**交互与自适应规则**：夜视使用点击选择 + 确认浮层，翻转使用开关即时提交。提交成功后播放画面立即应用效果。两项均不存在时隐藏分组。离线禁用，失败回退。

### 4.10 告警与提醒
**需求来源**：EVENT `stream_error`(101)、`env_abnormal`(104)、`sd_card_error`(102)、`bark_alert`(103)。
**展示规则**：告警条位于首页顶部。ERROR 红色、WARN 橙色、INFO 蓝色。多条同时存在时展示优先级最高的一条（ERROR > WARN > INFO）并标注总数。文案示例：“舍内温度偏高（31.2℃），店员已收到通知”“{宠物名}在叫（约 72 分贝），店员正在关注”。
**交互说明**：关闭只隐藏提示，不代表清除设备事件；页面重进后活动事件重新展示。恢复以设备上报为准：`stream_error` 随推流恢复解除，`env_abnormal` 随指标回到范围解除，`sd_card_error` 随 `sd_status` 回到正常解除，`bark_alert` 无恢复事件。事件输出参数为未知枚举时显示“未知异常”。

### 4.11 今日动态（日报、留言、时间线）
**需求来源**：平台能力。日报数字（进食次数、睡眠时长、玩耍时长、喝水次数）由平台根据 `pet_activity` 历史汇总。
**展示规则**：
- 日报：`pet_activity` 不存在时隐藏日报卡；无数据显示 `--`。
- 店员留言：平台提供，无留言时隐藏卡片。
- 时间线：倒序展示，类型用不同颜色圆点（进食、玩耍、睡眠、护理、投喂）。主人在本面板的投喂操作也写入时间线。无记录时显示空态。

### 4.12 设备状态详情
**需求来源**：`viewer_count`(7)、`wifi_rssi`(8)、`sd_status`(9)，R 可选，位于“更多”页。
**展示规则**：只读列表，字段不存在则隐藏该行；存在但无回报显示 `--`，观看人数 0 为有效值。三项全部缺失时隐藏分组。观看人数达到上限 4 时，再次点击实时流应得到 `result=2` 提示。

## 五、状态与异常处理

### 5.1 无数据
属性存在但无回报：数值显示 `--`，枚举显示“未知”，BOOL 不默认关闭，圆环显示空。有效 0（音量、活跃度、观看人数）正常显示。

### 5.2 离线与重连
离线：头部显示“离线”；播放中断；所有写操作、实时流、投喂、对讲禁用并保留最后有效值；点击不可用控件提示“设备离线，无法操作”。重连后重新拉取属性，恢复可操作，需用户重新点击实时流。

### 5.3 指令下发与状态同步
- RW 操作进入提交态，超时 5 秒；服务调用（`start_live`）超时 10 秒。
- 最终真值来自设备回报；失败、超时或回报不一致时恢复操作前的值。
- 同一属性连续操作只保留最后一次，旧回包不得覆盖新操作。
- 页面重进、前后台切换与设备重连后重新同步。

### 5.4 控制冲突与多终端
多个家庭成员可同时观看（上限 4 人）。任一终端调整画质会影响所有观看端。最后一个观看端退出时才停止推流。设备或店员侧的变化，以设备最新回报覆盖本地临时状态。

### 5.5 隐私与店铺边界
实时画面仅向该宠物的绑定主人开放，且受店铺营业时段约束。店内其他顾客与宠物可能入镜，具体隐私处理（如画面遮挡、分区）待确认。

## 六、验收用例

| 场景 | 前置条件 | 操作/上报 | 预期结果 |
|---|---|---|---|
| 正常观看 | 设备在线，店铺营业，`av_status=0` | 点击“实时流” | 先显示连接中，随后显示店内画面，LIVE 标记出现，`av_status` 为推流中 |
| 离线 | 设备离线 | 点击“实时流” | 封面灰色，按钮置灰，不调用服务 |
| 店铺休息 | 设备在线，休息时段 | 点击“实时流” | 封面显示休息文案与开放时间，不调用服务；播放中进入休息时段则停止播放 |
| 连接失败 | 设备在线 | `start_live` 返回 1/2/3，或 10 秒无回报 | 封面显示对应原因并提供重试 |
| 宠物状态映射 | 播放中 | `pet_activity` 依次上报 0～5 | 气泡与状态卡文案、图标、底色随之变化；画面中的宠物行为不作为验收依据（模拟） |
| 未知宠物状态 | 设备在线 | `pet_activity` 上报 9 | 显示“未知”，不默认选中任一状态 |
| 活跃度边界 | 设备在线 | `activity_level` 为 0 / 100 / 无回报 | 分别显示 0% 空圆环 / 100% 满圆环 / `--` |
| 环境提示 | 设备在线 | `env_temperature` 为 26.5 / 31.2 / 14.6 | 分别显示“舒适”/“偏热”/“偏冷”；后两者同时上报 `env_abnormal` 并出现橙色告警条；回到范围内告警解除 |
| 投喂成功 | `treat_left=2` | 点击投喂零食，`result=0` | 按钮显示投喂中，成功后剩余 1 次，时间线新增一条，出现提示 |
| 投喂用完/失败 | `treat_left=0`；或下发失败 | 点击按钮 | 前者按钮置灰“今日已投完”；后者提示失败且次数不变 |
| 抓拍 | 播放中 | 点击抓拍 | 提示成功，相册新增一张，Tab 角标 +1；未播放时按钮置灰 |
| 对讲 | 播放中 | 点击对讲 | `av_status` 变为对讲中，按钮高亮；再次点击恢复推流中 |
| 画质切换 | 设备在线 | 打开浮层选“标清”，确定 | 提交中后以设备回报更新首页与播放器；点击遮罩则不保存 |
| 枚举裁剪 | `video_quality` 仅 2 项 / 1 项 / 当前值未知 | 打开画质 | 仅显示保留项 / 只提示当前支持项 / 显示“未知”且无默认选中 |
| 写操作失败 | 设备在线 | 切换店内收音，指令失败 | 开关回退并提示“设置失败，已恢复设备当前值” |
| 音量边界 | 音量 100 / 0 | 查看加减按钮 | 对应按钮禁用，不下发越界值 |
| 仅必选能力 | 仅 `av_status`、`start_live`、`stop_live` | 打开面板 | 无状态卡与环境卡、无抓拍/投喂按钮、无相册与更多入口；实时流与对讲、动态页仍可用 |
| 级联隐藏 | 更多页三个分组的字段全部缺失 | 打开面板 | 隐藏“更多”入口；若当前在更多页则自动返回首页 |
| 多告警 | 同时上报 `stream_error`、`env_abnormal`、`bark_alert` | 打开首页 | 先显示 ERROR，并标注“共 3 条”；关闭仅隐藏提示，事件未解除 |
| 平台边界 | - | 查看能力说明 | 宠物档案、营业时段、日报、留言、时间线、相册存储标注为平台能力，不计入物模型统计 |
